## 常见MQ选择对比
### 1.Kafka
- 优点
    - 吞吐量极高，适合处理支付高并发
    - 水平扩展能力强，适合应对大规模用户增长
    - 有持久化，消息不易丢失
- 缺点
    - Kafka更偏向日志/流处理，延迟不是最优（ms级，但不一定sub-ms）
    - 要保证严格顺序和事务语义（exactly-once），实现较复杂
- 适合：交易量特别大（千万级TPS）、允许少量延迟的支付场景（如账务对账、清结算流）
### 2.RabbitMQ
- 优点
    - 延迟低，消息投递及时
    - 支持事务/确认机制。保证消息可靠送达
    - 丰富的路由机制（Direct，Fanout，Topic），灵活应对业务逻辑
- 缺点
    - 吞吐量比 Kafka 低一个量级（万级TPS）
    - 集群扩展性一般，需要额外组件来支撑大规模
- 适合：需要秒级确认、消息量中高、逻辑复杂的支付场景（如订单状态通知、实时扣款等）
### 3.RocketMQ
- 优点
    - 专门为金融支付、电商场景设计
    - 支持顺序消息、事务消息（强一致性，适合支付事务）
    - 吞吐量比 RabbitMQ 高，可靠性好
- 缺点
    - 生态相对 Kafka 弱一些
- 适合：支付/金融系统的核心交易流，尤其是对事务消息有强需求时
### 4.Pulsar
- 优点
    - 分布式架构，支持多租户、强扩展
    - 延迟比 Kafka 更低
- 缺点
    - 生态和成熟度略逊（运维复杂度也更高）
- 适合：大规模实时支付 + 云原生部署

综上：
核心支付链路（扣款、对账、保证事务一致性）：
👉 选 RocketMQ（因为事务消息、顺序消息支持好）。

外围异步通知、日志、埋点、风控流水：
👉 选 Kafka（高吞吐、做分析/大数据流处理）。

如果公司规模中小，架构不复杂：
👉 选 RabbitMQ，易用性和生态最好，上手快。
