### json和protobuf的区别
1.数据格式和可读性
- JSON 是一种文本格式。它使用键值对的方式来组织数据，并且具有很好的可读性。你打开一个 JSON 文件，可以很直观地理解它的内容。这种人性化的可读性使得 JSON 在前端开发、配置文件以及各种 API 接口中广受欢迎。

- Protobuf 是一种二进制格式。它的数据是经过编码压缩的，因此不可直接读懂。你需要一个 `.proto` 文件（数据模式定义）来解析数据。虽然这牺牲了可读性，但带来了极高的空间效率和解析速度。

2.性能和效率
- JSON 的解析和序列化通常需要更多的 CPU 和内存资源。由于是文本格式，它在传输时占用的带宽也更大，尤其是在数据量较大时。

- Protobuf 在这方面具有压倒性的优势。它的序列化速度比 JSON 快 5 到 10 倍，压缩后的数据大小比 JSON 小 3 到 10 倍。这是因为它采用了高效的二进制编码，省去了键名和冗余的格式字符（如 {}、[] 和 ,）。

3.数据模式和类型支持
- JSON 是无模式的，这意味着你不需要提前定义数据的结构。这提供了极大的灵活性，你可以随意添加或删除字段。然而，这也可能导致数据解析时出现类型不匹配或字段缺失的问题。

- Protobuf 是一种强类型、有模式的格式。你必须通过 .proto 文件定义数据的结构，包括字段名、类型和编号。这种强类型保证了数据的一致性，同时也提供了向前和向后兼容性。即使你修改了 .proto 文件，只要不改变字段编号，旧版本和新版本的程序通常也能正常工作。

4.语言支持
- JSON 是与 JavaScript 紧密相关的，几乎所有编程语言都内置了对 JSON 的支持，或者有成熟的库可以使用。

- Protobuf 由 Google 开发，提供了多种主流编程语言（如 C++, Java, Python, Go, C# 等）的代码生成工具。一旦定义了 .proto 文件，就可以自动生成各种语言的数据结构代码。
